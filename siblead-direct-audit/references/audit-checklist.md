# Чек-лист аудита Яндекс Директа для инфобизнеса и онлайн-школ

Методика собрана для онлайн-школ, экспертов, продюсеров и инфобизнеса. Типовые воронки: реклама → регистрация на вебинар, автовебинар или интенсив → продажа; реклама → лид-магнит → прогрев → продажа; реклама → заявка или диагностика → отдел продаж; реклама → прямая продажа трипваера или курса.

Основа порогов и схемы оценки — открытые проекты (см. «Источники»). Всё адаптировано под инфобизнес.

**Все пороги — ориентир, а не закон.** В отчёте у каждой находки указывай порог, по которому она сработала.

## Пять обязательных модулей

Каждый аудит включает пять модулей с отдельной методикой. Их результаты идут в проверки ниже и отдельными блоками в отчёт:

| Модуль | Методика | Проверки |
|---|---|---|
| 1. Минус-фразы | `minus-words.md` | B1, B6, K7 |
| 2. Мусорные площадки РСЯ | `placements.md` | B2, B3 |
| 3. Структура кампаний | `structure.md` | S1–S7, K4, K6, T1, T4 |
| 4. Цели и оптимизация | `goals.md` | M1–M7, P10, S2, S3 |
| 5. Креативы | `creatives.md` | A1–A10, P11 |

Если для модуля нет данных, всё равно дай то, что можно без них: превентивный минус-список для ниши, базовый список мусорных площадок, целевую структуру под бюджет и воронку, правильную схему целей. Пометь, что это рекомендация без проверки на данных.

## Статусы

- `PASS` — всё в порядке;
- `WARN` — есть замечания;
- `FAIL` — проблема;
- `NA` — проверить нельзя (нет данных, нет ответа, не относится к этому кабинету). В оценку не идёт.

Не ставь `FAIL` из-за нехватки данных.

## Единые определения

Все файлы скилла ссылаются на эти определения. Если где-то сказано иначе — действует этот раздел.

**Базис качества (самый глубокий этап).** Любое сравнение качества — кампаний, ЕПК и сетей против поиска, сегментов, площадок, запросов, креативов, недель в «Качелях», находок — делай по **самому глубокому этапу, у которого достаточный объём**, в порядке: **оплата → заявка → пришёл на вебинар → квалифицированная регистрация → регистрация.** Глубже нет данных или мало событий — бери следующий этап. В отчёте всегда пиши, по какому этапу сравнивал.

**Достаточный объём.** Этап годится для сравнения, если в **каждом** сравниваемом сегменте (кампании, площадке, неделе, объявлении) **≥10 событий** этого этапа. Исключение: для продаж в «Качелях» — ≥15–20 продаж суммарно в «хороших» и «плохих» неделях. Меньше — переходи на следующий, более частый этап; а если и там мало — вывод помечай «гипотеза, проверить тестом».

**Основные кампании** — крупнейшие по расходу, вместе дающие ≥80% расхода за период (минимум 1–2 кампании).

**Заметный расход** — ≥5% расхода аккаунта за период или ≥ tCPL.

**Цена этапа** = расход / число событий этапа. **Допустимая цена этапа** = допустимый CAC × доля людей с этого этапа, которые доходят до оплаты. Без продаж — сравнивай этап с другими кампаниями и сегментами аккаунта.

**Средний чек** — со слов человека или из продаж. **Допустимый CAC** = средний чек × целевая ДРР (со слов человека; по умолчанию 30%).

**tCPL** (целевая цена регистрации) — по порядку: 1) со слов человека; 2) допустимый CPL = средний чек × конверсия регистрация → оплата × целевая ДРР (по умолчанию 30%; пример: 50 000 ₽ × 2% × 30% ≈ 300 ₽); 3) только если нет ни того ни другого — средний CPL аккаунта. Какой вариант взят — пиши в «Как считали».

**Лаг продаж.** Продажи берутся за период рекламы + лаг (со слов человека; по умолчанию 14 дней). Кампании моложе лага по продажам не оцениваются.

**Бюджет в месяц** = расход за период / дней × 30. Если человек назвал свой месячный бюджет на рекламу — бери его.

**Главная потеря в воронке** — шаг с наименьшим отношением «факт / нижняя граница ориентира» (например, доходимость 16% при ориентире 30% → 0,53). Если ниже ориентира несколько шагов — главный тот, где отношение меньше.

**Деньги под риском без задвоений.** Каждая трата попадает в первую подходящую строку: нецелевые запросы (B1) → мусорные площадки (B2, затем B3) → ключи без результата (B4) → кампании без результата (B5).

## Базовые числа инфобизнеса

Определи до проверок и покажи в отчёте:

- **Воронка** — шаги: **клики → регистрации → пришли на вебинар → заявки → продажи**. Для каждого шага: количество, цена шага, конверсия с прошлого шага — в целом и по кампаниям (правила — в `data-handling.md`). Воронка без вебинара (лид-магнит, диагностика, прямая продажа) — шаг «пришли» пропускай, P4 и P5 — `NA`.
- **Сравнение кампаний — по базису качества**, а не по цене регистрации: дешёвая регистрация, которая не доходит до вебинара, — самый частый слив в инфобизнесе (особенно в РСЯ).
- **Ориентиры воронки SibLead** (если у человека есть свои нормы — бери их и скажи об этом): из 100 перешедших регистрируются **от 9**; из 100 зарегистрировавшихся приходят на вебинар **от 30 (норма), от 45 — хорошо**; из 100 пришедших оставляют заявку 5–15; из 100 заявок оплачивают 15–30; регистрация → оплата 0,5–3%.
- **Лид** — что считается результатом рекламы: регистрация на вебинар, заявка, скачивание лид-магнита, покупка трипваера. **CPL** — цена лида (расход / лиды).
- **Есть продажи** → главные метрики: выручка, ROMI, ДРР, CAC по кампаниям. Деньги в отчёте считай от продаж, а не только от регистраций.
- **Нет конверсий вообще** — проверки с tCPL ставь `NA`. Слив считай по запасному правилу: ≥5 кликов и расход ≥5 средних цен клика без признаков целевого трафика.

## Минимум данных для выводов

- Выводы по CTR, отказам и конверсии — только при **≥30 кликах** у строки.
- Минусовать запрос — при **≥5 кликах**. Исключение: явный мусор (сливы, складчины, пиратство) минусуется при любом числе кликов.
- Денежный сигнал **расход ≥ tCPL при 0 регистраций** работает при любом числе кликов.
- Кампания без оплат — проблема, только если её **расход ≥ среднего чека**. Иначе — мало данных.
- Сравнение качества — только при достаточном объёме (см. «Единые определения»).
- **Стратегии с оплатой за конверсии:** правила «расход без конверсий» смягчай. Вместо этого проверяй цель оплаты (M2) и качество лидов (P3, M4).

## Подсказки для модулей минус-фраз и площадок

Типы нецелевых запросов — в `minus-words.md`, типы мусорных площадок и признаки фрода — в `placements.md`. Решение по каждому запросу и площадке — по смыслу и цифрам, не по совпадению слов.

## Рекомендуемый шаблон UTM для Директа

Если разметки нет или она неоднозначная (M5, M6, P9), дай в отчёте готовый шаблон для параметров ссылки в кампании:

```
utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}&utm_term={keyword}&utm_placement={source}
```

И объясни: метки должны передаваться с лендинга в форму регистрации и дальше в заказ на платформе (GetCourse, CRM), иначе продажи не связать с рекламой.

## Вопросы человеку

Задай одним сообщением в начале. Не настаивай, если человек не знает:

1. Что продаёте, какой средний чек, есть ли рассрочка? → базовые числа, P
2. Как устроена воронка: живой вебинар, автовебинар, интенсив, лид-магнит, диагностика? Что считается регистрацией и заявкой? → шаги воронки, M2
3. Сколько готовы платить за регистрацию или какую долю выручки на рекламу (ДРР)? → tCPL, P1
4. Через сколько после регистрации обычно покупают? → лаг продаж
5. Стало ли хуже в последнее время — продаж меньше, лиды нецелевые? С какого момента? Или результат скачет от недели к неделе? Когда были эфиры? → диагностика «Что изменилось» (`data-handling.md`), D13
6. Можете прислать по шагам воронки выгрузки с UTM: регистрации, дошедшие до вебинара, заявки, оплаты (GetCourse, Bizon, CRM или ссылка на таблицу)? Или хотя бы продажи. → P, M3, M6
