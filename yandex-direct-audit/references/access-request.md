# Этап 2. Заявка на доступ к API Директа

Официально: https://yandex.ru/dev/direct/doc/ru/access-request и https://yandex.ru/dev/direct/doc/ru/troubleshooting/register

## Перед подачей

1. В аккаунте Директа есть хотя бы одна кампания (можно черновик). Без неё страница «Настройки API» не открывается.
2. Есть ClientID приложения с правом `direct:api` (этап 1).
3. Вход под тем же логином, под которым создавалось приложение.

## Где подавать

- https://direct.yandex.ru/registered/main.pl?cmd=apiSettings
- или Директ → «Инструменты» → «API».
- При первом входе — пользовательское соглашение API. Его читает и принимает человек.
- Вкладка «Мои заявки» → «Новая заявка» (или «Подать заявку»).

## Как заполнять форму

Набор полей меняется. Прочитай форму целиком, потом заполняй. Типичные поля:

| Поле | Что ставить |
|---|---|
| Приложение / ClientID | Выбрать из списка приложение из этапа 1. |
| Тип доступа (если есть) | Для аудита реальных кампаний — полный/рабочий доступ. Тестовый даёт только песочницу. Если форма разрешает сначала только тестовый — подать его, потом заявку на полный. |
| Почта | Реальная, которую человек читает. |
| Компания / ФИО / контакты / сайт | Данные человека. Спроси, не выдумывай. Сайт — тот, что рекламируется. |
| Как будете использовать API / тип использования | Обычно вариант про управление/статистику собственных кампаний. Агентство — «кампании клиентов агентства». |
| Описание приложения / функциональность | Шаблон ниже. |
| Методы / сервисы API | Если спрашивают: Campaigns, AdGroups, Ads, Keywords, Reports — только чтение (`get`). |
| Прототип / скриншоты / ссылка | Если обязательно — подойдёт описание скрипта и пример отчёта; спроси человека, что приложить. |

## Шаблоны текстов

Подставь реальные данные. Текст должен быть конкретным: размытые описания — главная причина отказа.

**Свои кампании (рекламодатель):**

> Внутренний инструмент компании <Название> (<сайт>) для анализа эффективности собственных рекламных кампаний в Яндекс Директе. Приложение работает только в режиме чтения: получает список кампаний, групп, объявлений и ключевых фраз (Campaigns.get, AdGroups.get, Ads.get, Keywords.get) и статистику через сервис Reports (отчёты по кампаниям, ключевым фразам, поисковым запросам и площадкам). Данные используются для внутреннего аудита: поиск нецелевых запросов и площадок, неэффективных ключевых фраз и перерасхода бюджета. Изменения в кампании через API не вносятся. Доступ только у сотрудников компании, данные третьим лицам не передаются. Ориентировочная нагрузка — несколько запусков в неделю, десятки запросов за запуск.

**Агентство / специалист для клиентов:**

> Инструмент агентства <Название> (<сайт>) для аудита и отчётности по кампаниям клиентов агентства в Яндекс Директе. Работает только на чтение: Campaigns.get, AdGroups.get, Ads.get, Keywords.get и сервис Reports. По каждому клиенту (Client-Login) формируется отчёт с рекомендациями: нецелевые поисковые запросы, площадки РСЯ с низкой эффективностью, ключевые фразы без конверсий, проблемы с расширениями объявлений. Правки в кампании вносит специалист вручную в веб-интерфейсе. Доступ только у сотрудников агентства, данные клиентов третьим лицам не передаются.

## Перед отправкой

Покажи человеку все поля одним списком и спроси «Отправляем?». Отправляй только после явного «да».

## После отправки

- Статус — во вкладке «Мои заявки», ответ — на почту. Срок — обычно от нескольких часов до нескольких рабочих дней.
- После правки заявки она уходит на повторное рассмотрение.
- Без одобренной заявки API отвечает ошибкой (например, 58 «Незавершённая регистрация» / приложение не имеет доступа) — это нормально, ждём.

## Если отклонили

Прочитай причину в заявке и исправь именно её. Частые причины и что делать:

| Причина | Исправление |
|---|---|
| Описание слишком общее | Переписать по шаблону: конкретные сервисы API, что делает инструмент, кто пользуется, только чтение. |
| Нерабочая/чужая почта, сайт, контакты | Указать реальные данные человека. |
| Не указан или непонятен прототип | Описать сценарий по шагам, приложить пример отчёта/скриншот вывода скрипта. |
| Приложение без права `direct:api` или под другим логином | Исправить приложение (этап 1) и выбрать его заново. |
| Заявлен «коммерческий сервис», а описан внутренний скрипт (или наоборот) | Выбрать тип использования, совпадающий с описанием. |

Если причина неясна — предложи человеку написать в поддержку API Директа со страницы заявки, подготовь ему текст письма.
