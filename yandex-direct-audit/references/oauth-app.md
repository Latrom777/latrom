# Этап 1. Приложение на Яндекс OAuth — что заполнять

Страница: https://oauth.yandex.ru/client/new
Официальная инструкция: https://yandex.ru/dev/direct/doc/ru/register

## Под каким логином

- Свои кампании — под тем же логином, на котором кампании в Директе.
- Агентство — под логином агентства (главным или представителем).
- Приложение регистрирует только «разработчик» (тот, кто будет делать запросы). Другим пользователям для выдачи токена регистрировать ничего не нужно.

## Поля

Интерфейс иногда меняется, ориентируйся по смыслу.

| Поле | Что писать |
|---|---|
| Название вашего сервиса | Человекопонятно: «Аудит рекламы <компания>», «Отчёты Директ <компания>». Без слов «test», «asdf». |
| Иконка | Не обязательно. |
| Платформы / тип приложения | «Для доступа к API или отладки». Если такого варианта нет — «Веб-сервисы», Redirect URI: `https://oauth.yandex.ru/verification_code` |
| Доступ к данным / права | Раздел «Яндекс Директ» → «Использование API Яндекс Директа» (`direct:api`). Остальное не отмечать — лишние права только мешают одобрению. |
| Почта для связи | Реальная почта человека (на неё придут уведомления). Спроси, какую указать. |

## После создания

- На странице приложения будет **ClientID** — сохрани его, он нужен для заявки и токена. Это не секрет.
- **Client secret** для получения токена по схеме ниже не нужен. Не выводи его в чат.
- Изменить права можно позже на странице приложения («Редактировать»).

## Частые проблемы

- Нет раздела «Яндекс Директ» в правах — выбран не тот тип платформы; переключи на «Для доступа к API или отладки» / «Веб-сервисы».
- Создал под чужим логином — проще создать новое приложение под правильным.
