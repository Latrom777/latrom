# Аудит Яндекс Директа

Скилл ведёт человека по четырём этапам. Пропускай этап, если у человека уже есть то, что он даёт.

| Этап | Результат | Можно пропустить, если |
|---|---|---|
| 1. Приложение на Яндекс OAuth | ClientID | приложение с правом `direct:api` уже есть |
| 2. Заявка на доступ к API в Директе | одобренная заявка | заявка уже одобрена |
| 3. OAuth-токен | токен в `YANDEX_DIRECT_TOKEN` | токен уже есть |
| 4. Выгрузка и аудит | отчёт с находками и планом | — |

Начни с одного вопроса: «Есть ли у вас уже токен API Директа или одобренная заявка?» — и прыгай на нужный этап.

## Жёсткие правила

- **Логин и пароль вводит только человек.** Ты не спрашиваешь пароль, не вводишь его и не обходишь капчу/2FA. Дошёл до входа — попроси человека войти в открытом окне браузера и подожди.
- **Перед любой кнопкой «Создать», «Отправить», «Сохранить» — покажи человеку, что заполнено, и получи явное «да».** Заявку подаёт человек от своего имени.
- **Токен — секрет.** Не печатай его в чат целиком, не коммить, не вставляй в отчёт. Храни в переменной окружения `YANDEX_DIRECT_TOKEN` или в файле `.env`, который в `.gitignore`.
- **Аудит только читает.** Используются только методы `get` и Reports. Ничего в кампаниях не меняй, даже если просят «сразу поправить» — дай список правок, человек вносит их сам.
- **Интерфейс Яндекса меняется.** Названия полей ниже — ориентир. Всегда читай живую страницу и заполняй то, что на ней реально есть. Если поле непонятно — спроси человека, не выдумывай.

## Каким браузером работать

Выбирай первое доступное:

1. **Браузерные инструменты в этой сессии** (Claude in Chrome, встроенный браузер, Playwright MCP и т.п.) — лучший вариант: человек уже залогинен в Яндексе в своём браузере. Перед первым шагом загрузи соответствующий скилл браузера, если он есть.
2. **Скрипт на [browser-use](https://github.com/browser-use/browser-use)** — `scripts/setup_access.py`. Открывает видимое окно Chromium с отдельным профилем, ИИ-агент проходит этапы 1–2, а на входе в аккаунт и перед отправкой формы останавливается и спрашивает человека в терминале. Запуск — см. «Скрипты» ниже.
3. **Без браузера** — просто веди человека по шагам из `references/` текстом: он кликает, ты подсказываешь, что писать в каждое поле.

## Этап 1. Приложение на Яндекс OAuth

Подробно: `references/oauth-app.md`. Коротко:

1. Открыть https://oauth.yandex.ru/client/new (вход под тем логином, у которого рекламные кампании, или под логином представителя/агентства).
2. Название сервиса — понятное, например «Аудит рекламы ООО Ромашка».
3. Платформа — вариант «Для доступа к API или отладки» (если такого нет — «Веб-сервисы» и Redirect URI `https://oauth.yandex.ru/verification_code`).
4. Доступ к данным — найти «Яндекс Директ» и отметить «Использование API Яндекс Директа» (`direct:api`). Больше ничего не отмечать.
5. Почта для связи — реальная.
6. Показать человеку заполненное → по «да» нажать «Создать приложение».
7. Сохранить **ClientID** (он не секрет). Client secret не нужен и в чат не выводится.

## Этап 2. Заявка на доступ к API

Подробно и с готовыми текстами: `references/access-request.md`. Коротко:

1. В Директе должна быть **хотя бы одна кампания** (хоть черновик), иначе страница настроек API недоступна.
2. Открыть https://direct.yandex.ru/registered/main.pl?cmd=apiSettings (или Директ → «Инструменты» → «API»). При первом входе — принять пользовательское соглашение (человек читает и соглашается сам).
3. Вкладка «Мои заявки» → «Новая заявка».
4. Выбрать ClientID приложения из этапа 1, заполнить поля по живой форме, тексты брать из шаблонов в `references/access-request.md`, подставляя данные человека.
5. Показать человеку всё заполненное → по «да» отправить.
6. Сказать человеку: рассмотрение обычно занимает от нескольких часов до нескольких рабочих дней, статус — на той же вкладке «Мои заявки», ответ приходит на почту. Если отклонили — открой `references/access-request.md`, раздел «Если отклонили».

Если в форме есть выбор тестового и полного доступа: тестовый даёт только песочницу (`api-sandbox.direct.yandex.com`), для аудита реальных кампаний нужен полный. Для своих кампаний честно пиши, что это внутренний инструмент только для чтения статистики.

## Этап 3. Токен

Когда заявка одобрена:

1. Открыть в браузере, где человек залогинен под нужным логином:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`
2. Человек нажимает «Разрешить». Токен будет на странице (или в адресе после `#access_token=`).
3. Попроси человека самого сохранить токен:
   ```bash
   export YANDEX_DIRECT_TOKEN='y0_...'
   ```
   или положить в `.env` рядом со скриптом. В чат токен не вставлять.
4. Если кампании ведёт агентство или аккаунт — клиент агентства, понадобится логин клиента (`--client-login`).

## Этап 4. Выгрузка и аудит

1. Выгрузка (только чтение, ~1–5 минут):
   ```bash
   pip install -r scripts/requirements.txt   # только requests
   python scripts/direct_fetch.py --days 30 --out direct_audit_data
   # агентство:   --client-login имя-клиента
   # песочница:   --sandbox
   ```
   Скрипт складывает в папку `campaigns.json`, `adgroups.json`, `ads.json`, `keywords.json`, отчёты `report_*.tsv` и короткую сводку `summary.md`. Если какой-то отчёт не выгрузился — скрипт пишет предупреждение и идёт дальше; отметь это в аудите.
2. Прочитай `summary.md`, затем нужные файлы. Большие TSV не читай целиком — сортируй/фильтруй (`sort`, `awk`, `python -c`), смотри топы по расходу.
3. Пройди чек-лист `references/audit-checklist.md` по порядку. Каждая находка — с цифрами из данных, а не общими словами.
4. Выдай отчёт в формате из `references/audit-checklist.md` («Формат отчёта»): сначала 3–5 главных проблем по деньгам, потом всё остальное по разделам, в конце — план правок по приоритету. Если человек просит файл или страницу — оформи отчёт как документ.

## Скрипты

- `scripts/direct_fetch.py` — выгрузка данных через API v5 и Reports. Зависимость: `requests`. Токен из `YANDEX_DIRECT_TOKEN` или `.env`.
- `scripts/setup_access.py` — браузерный агент на browser-use для этапов 1–2 (и открытия страницы токена). Требует Python ≥ 3.11 и ключ LLM:
  ```bash
  pip install browser-use
  export ANTHROPIC_API_KEY=...          # или OPENAI_API_KEY / GOOGLE_API_KEY, см. --llm
  python scripts/setup_access.py --step app      # создать приложение
  python scripts/setup_access.py --step request --client-id <ClientID>   # подать заявку
  python scripts/setup_access.py --step token --client-id <ClientID>     # открыть страницу токена
  ```
  Окно браузера видимое, профиль хранится в `~/.yandex-direct-audit-browser`, так что входить в Яндекс нужно один раз.
