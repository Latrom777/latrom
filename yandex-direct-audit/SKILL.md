# Аудит Яндекс Директа

Скилл для владельцев бизнеса и маркетологов, обычно не программистов. Говори просто, без жаргона API, по одному шагу за раз.

## Старт: выбери путь

Спроси одним сообщением:

> Можно сделать аудит двумя способами:
> **1. Быстро (15 минут)** — вы скачиваете 3–4 отчёта из Директа и присылаете сюда. Ничего подключать не нужно.
> **2. Полностью через API** — точнее и можно повторять каждую неделю, но Яндексу нужно одобрить доступ (обычно от нескольких часов до нескольких дней). Помогу всё оформить.
> Если у вас уже есть токен API Директа — сразу переходим к выгрузке.

- Путь 1 → раздел «Быстрый аудит».
- Путь 2 → «Полный аудит через API».
- Если человек сразу прислал файлы отчётов — это путь 1, ничего не спрашивай, начинай разбор.
- Хорошая тактика: сделать быстрый аудит сразу, а параллельно подать заявку на API для регулярных проверок.

## Жёсткие правила

- **Логин, пароль, SMS-коды, капчу вводит только человек.** Ты их не спрашиваешь и не вводишь.
- **Перед любой кнопкой «Создать», «Отправить», «Сохранить», «Принимаю» — покажи всё заполненное и получи явное «да».**
- **Аудит ничего не меняет в кабинете.** Только чтение. Правки человек вносит сам по твоему плану.
- **Не выдумывай данные человека** (компания, сайт, почта, телефон) — спрашивай.
- **Токен — как пароль.** Не повторяй его в ответах, не вставляй в отчёт. После аудита посоветуй отозвать токен, если регулярные проверки не нужны (раздел «Токен»).
- **Интерфейс Яндекса меняется.** Названия кнопок ниже — ориентир. Если на экране у человека иначе — ориентируйся на его описание или скриншот.

## Где ты запущен

Определи по доступным инструментам и веди себя соответственно:

| Среда | Браузер | Скрипты | Токен |
|---|---|---|---|
| Claude Code / Desktop с доступом к компьютеру | браузерные инструменты сессии, если есть, иначе `scripts/setup_access.py` | запускаются локально | человек сам делает `export YANDEX_DIRECT_TOKEN=...` или кладёт в `.env` |
| claude.ai (веб/приложение) | обычно нет — веди по шагам текстом, проси скриншоты | в песочнице, если включено выполнение кода | человек вставляет токен в чат; передай его скрипту через переменную окружения в той же команде, не повторяй в тексте |

В claude.ai песочнице может быть закрыт доступ в интернет. Если скрипт падает с ошибкой соединения к `api.direct.yandex.com` — скажи человеку разрешить этот домен (или доступ в интернет) в настройках выполнения кода Claude, либо перейти на быстрый аудит по выгрузкам.

Пути к файлам скилла (`scripts/…`, `references/…`) — относительно папки, где лежит этот SKILL.md.

## Быстрый аудит (по выгрузкам, без API)

1. Дай человеку инструкцию из `references/manual-export.md` — какие отчёты скачать и с какими настройками. Давай её по одному отчёту, если человек путается.
2. Принимай файлы (xlsx/csv/tsv) в любом порядке. Если чего-то не хватает — делай аудит по тому, что есть, и пиши в «Ограничениях», что не проверено.
3. Читай файлы кодом (pandas/csv), а не глазами: в выгрузках Директа сверху бывают строки-заголовки и снизу «Итого» — найди строку с названиями колонок, отрежь итог. Деньги могут быть с запятой и пробелами.
4. Аудит — по `references/audit-checklist.md`, отчёт — в формате оттуда же.

## Полный аудит через API

| Этап | Результат | Пропустить, если |
|---|---|---|
| 1. Приложение на Яндекс OAuth | ClientID | приложение с правом `direct:api` уже есть |
| 2. Заявка на доступ к API | одобренная заявка | уже одобрена |
| 3. Токен | токен | токен уже есть |
| 4. Выгрузка и аудит | отчёт | — |

### Каким браузером работать (этапы 1–3)

1. Браузерные инструменты в сессии (Claude in Chrome, встроенный браузер, Playwright MCP) — лучший вариант, человек уже залогинен. Перед первым шагом загрузи скилл этого браузера, если он есть.
2. Скрипт `scripts/setup_access.py` на [browser-use](https://github.com/browser-use/browser-use) — если ты на компьютере человека и есть Python ≥ 3.11 и ключ LLM. Видимое окно, вопросы человеку в терминале.
3. Без браузера — веди текстом по `references/`: человек кликает, ты говоришь, что писать в каждое поле. Проси скриншот, если что-то не так.

### Этап 1. Приложение на Яндекс OAuth

Подробно: `references/oauth-app.md`.

1. https://oauth.yandex.ru/client/new — под логином, где кампании (или логином агентства).
2. Название — «Аудит рекламы <компания>».
3. Платформа — «Для доступа к API или отладки» (нет такой — «Веб-сервисы», Redirect URI `https://oauth.yandex.ru/verification_code`).
4. Права — «Яндекс Директ» → «Использование API Яндекс Директа» (`direct:api`). Больше ничего.
5. Почта — реальная. Показать → «да» → «Создать приложение».
6. Сохранить **ClientID** (не секрет). Client secret не нужен.

### Этап 2. Заявка на доступ

Подробно и с готовыми текстами: `references/access-request.md`.

1. В Директе нужна хотя бы одна кампания (можно черновик).
2. https://direct.yandex.ru/registered/main.pl?cmd=apiSettings (или «Инструменты» → «API»). Соглашение принимает человек.
3. «Мои заявки» → новая заявка → выбрать ClientID → поля по живой форме, тексты из шаблонов.
4. Показать → «да» → отправить.
5. Сказать: ответ придёт на почту, статус — на вкладке «Мои заявки». Пока ждём — можно сделать быстрый аудит.
6. Отказали → `references/access-request.md`, «Если отклонили».

Если в форме выбор тестового и полного доступа: тестовый — только песочница, для реальных кампаний нужен полный.

### Этап 3. Токен

1. После одобрения открыть под нужным логином:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`
2. Человек нажимает «Разрешить», копирует токен.
3. Локально: `export YANDEX_DIRECT_TOKEN='...'` или строка `YANDEX_DIRECT_TOKEN=...` в `.env` рядом с местом запуска. В claude.ai — вставить в чат.
4. Агентство или клиент агентства — понадобится логин клиента (`--client-login`).
5. Отозвать токен потом: https://id.yandex.ru/security → «Доступы» / «Входы и устройства» (или страница приложения на oauth.yandex.ru). Скажи об этом в конце аудита.

### Этап 4. Выгрузка и аудит

```bash
pip install requests
python scripts/direct_fetch.py --days 30 --out direct_audit_data
# клиент агентства: --client-login имя   ·   песочница: --sandbox
```

В claude.ai: `YANDEX_DIRECT_TOKEN='<токен>' python scripts/direct_fetch.py ...` одной командой, токен в ответах не повторяй.

Скрипт кладёт `campaigns.json`, `adgroups.json`, `ads.json`, `keywords.json`, `report_*.tsv` и `summary.md`. Что не выгрузилось — перечислено в конце `summary.md`.

Расшифровка ошибок: 53 — неверный/просроченный токен (этап 3); 58 — заявка ещё не одобрена (этап 2); 54/8800 — нет прав на этот аккаунт (проверь `--client-login`).

Дальше: прочитай `summary.md`, большие TSV анализируй кодом (топы по расходу), пройди `references/audit-checklist.md`, выдай отчёт в формате оттуда же.

## Отчёт

- Формат — `references/audit-checklist.md`, «Формат отчёта». Начинай с денег: сколько уходит впустую и на что.
- Минус-слова и площадки для запрета — готовыми блоками для копирования.
- Если среда умеет создавать файлы/документы — предложи сохранить отчёт файлом, чтобы переслать подрядчику.
- В конце: что сделать сегодня, через сколько повторить аудит (обычно через 2–4 недели после правок), и про отзыв токена, если он использовался.
